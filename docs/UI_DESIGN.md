> **正式决策（2026-09-04）**：LearnLab 的桌面 UI 直接以 VSCode Workbench 作为主要对标对象。对标范围包括布局、面板组织、标签页、命令入口、状态栏、通知和交互密度；图标、品牌、文案和学习内容模型使用 LearnLab 自己的设计。顶部原生 Menubar、应用内命令入口、主侧边栏、中央主窗口、可选辅助侧栏和底部面板都属于正式布局；图标最后实现，前期使用占位符。

### UI 冻结边界

当前已经冻结的是 Workbench 的区域组成、Activity Bar 的一级功能、章节树的交互、单一 Editor Group、不恢复关闭标签、AI 等辅助视图默认进入右侧辅助侧栏、状态栏核心信息、通知等级/位置/消失提示以及 Fatal 隔离行为。

仍未冻结的是各区域精确尺寸和响应式断点、普通视图的默认落点和记忆方式、标签页的预览/固定/脏状态、搜索结果和替换确认的全部细节、通知堆叠与历史、快捷键默认值、UI 原型与正式 renderer 的长期边界，以及正式图标和最终视觉细节。实现这些部分时以[公开决策索引](DECISIONS.md)的 `UI-*` 条目为准。

截至 2026-09-15，独立原型仍可单独构建，正式 desktop renderer 已接入 Workbench 区域和真实数据，但章节树、设置入口、搜索状态、平台标题区和快速打开样式没有完整保留原型效果，**尚未通过用户视觉验收**。具体问题、VSCode 源码参考和待补操作见 [Workbench 外观反馈与源码研究](reviews/2026-09-15-workbench-visual-feedback.md)（`UIR-01` 至 `UIR-09`）；按本轮要求先记录，暂不修改 UI 外观。

两者是否长期共享组件、原型何时删除仍未冻结；正式 renderer 中的替换、实验执行、插件 UI、原生菜单、Fatal 隔离和最终图标不得因已有外观而视为完成。功能测试和区域不重叠的检查不能替代原型一致性检查及用户视觉验收。

## 1. 设计目标与边界

LearnLab 不是普通的 Markdown 网页阅读器，而是一个**以学习内容为中心、可由插件扩展的本地学习工作台**。

UI 设计目标按优先级排列：

1. 直接采用成熟的 Workbench 空间组织方式，降低复杂功能加入后的重构成本。
2. 让第一次使用的用户能够清楚地区分实验包、章节、实验、日志、插件和运行环境。
3. 保持中央教程内容适合长文阅读，不把所有内容强行做成代码编辑器。
4. 让插件可以在受控权限下注册面板、命令、按钮、标签页和状态栏项目。
5. 先实现静态且可测试的 UI 壳，再接入数据库、插件执行和实验运行时。

### 不做的事情

- 不复制 VSCode 的品牌、图标资源、欢迎页文案或产品名称。
- 不因为外观对标 VSCode 就强制实现 Git、调试器、远程开发等 LearnLab 不需要的功能。
- 不让插件直接向 DOM 注入任意页面；插件 UI 必须通过宿主定义的视图注册接口接入。
- 不把阅读进度、实验历史和插件设置混在 UI 状态中；持久化边界由数据模型文档决定。

## 2. 正式 Workbench 布局

### 2.1 默认窗口结构

LearnLab 默认采用 VSCode 风格的 Workbench，而不是旧的“简单两栏”布局。顶部需要区分操作系统原生菜单和应用内标题/命令区域：macOS 的菜单由系统 Menubar 承载，Windows/Linux 则在应用窗口顶部显示 Menubar；两者的菜单命令保持一致。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 原生 Menubar：文件 / 编辑 / 查看 / 转到 / 运行 / 窗口 / 帮助          │
├────────────────────────────────────────────────────────────────────┤
│ 应用内标题区：当前学习区/实验包 · 命令入口/快速打开 · 布局            │
├──────┬──────────────────────┬──────────────────┬────────────────────┤
│      │                      │ 编辑器标签页     │                    │
│      │                      ├──────────────────┤                    │
│功能栏│    主侧边栏          │                  │  辅助侧栏（可选）  │
│      │    当前功能视图      │  中央主窗口       │  AI / 插件辅助视图  │
│      │                      │  教程 / 实验      │  可切换标签         │
│      │                      │  笔记 / 插件      │                    │
├──────┴──────────────────────┴──────────────────┴────────────────────┤
│ 底部面板（按需：终端 / 输出 / 日志 / 错误 / 实验历史）                │
├────────────────────────────────────────────────────────────────────┤
│ 状态栏：核心阅读进度/已加载插件 + 插件可注册的左/中/右状态项          │
└────────────────────────────────────────────────────────────────────┘
```

布局区域的职责：

| 区域 | 默认职责 | 插件是否可扩展 |
|:---|:---|:---:|
| 原生 Menubar | 文件、编辑、查看、转到、运行、窗口、帮助、近期打开文件和窗口级命令 | 插件只能注册受控命令/菜单项，不能改写原生菜单结构 |
| 应用内标题区 / Command Center | 当前学习区/实验包上下文、快速打开/命令入口和布局操作；不提供应用级返回/前进按钮 | 可注册命令和操作，不直接改写窗口框架 |
| 功能栏 Activity Bar | 切换章节、搜索和替换、实验、插件、依赖、学习区、文件资源管理器 | 可以注册新的受控入口，但 MVP 先固定核心入口 |
| 主侧边栏 Primary Sidebar | 当前功能的树、列表、筛选器和摘要 | 可以注册受控侧边栏视图 |
| 编辑器标签页 Editor Tabs | 教程、实验、笔记、日志和插件视图 | 可以注册标签页类型，但不支持多 Editor Group |
| 中央主窗口 Editor Area | 用户当前的主要学习或实验内容 | 可以注册受控内容视图 |
| 辅助侧栏 Auxiliary Sidebar | 用户选择的辅助视图；AI 等明确的辅助插件默认固定在此 | 可由插件注册标签；普通视图允许用户选择主窗口或辅助侧栏 |
| 底部面板 Bottom Panel | 核心主要显示实验历史等宿主内容；终端、输出和诊断由插件按需注册 | 只能通过面板 API 注册；显示时用右侧关闭按钮收起，重新打开从顶部 Menubar 进入 |
| 状态栏 Status Bar | 当前文档阅读进度、已加载插件数量、未预览消息和插件状态项 | 插件可在左/中/右槽位注册状态项，受权限和数量限制 |
| 通知宿主 Notification Host | 右下角运行时消息气泡；与日志内容分离 | 插件可提交结构化通知，但等级和生命周期由宿主控制 |

**窗口放置规则**：视图注册协议提供 `preferredLocation: main | auxiliary | bottom` 和 `userCanMove`。实验视图默认在中央主窗口打开，用户可将适合辅助阅读的视图移到辅助侧栏；AI 对话、实时诊断等明确的辅助插件默认在辅助侧栏。MVP 不支持多个 Editor Group，但辅助侧栏拥有独立标签组。

### 2.1.1 原生 Menubar 与应用内命令入口

- Menubar 是跨平台正式功能，不因 macOS 将菜单绘制在系统顶部而省略；Electron 主进程统一创建菜单模板。
- Menubar 负责稳定的全局操作：打开/切换学习区、近期打开文件、关闭标签、设置、退出、帮助和开发者操作。
- 应用内标题区负责当前上下文和快速操作，不复制全部 Menubar；命令入口可搜索核心命令和插件命令。
- 菜单命令必须拥有稳定的 command ID，后续快捷键和插件注册都引用 command ID，而不是依赖显示文本。
- 具体菜单文案、快捷键和正式图标属于后续实现细节；布局骨架阶段可先使用文字占位。

平台外壳待修要求（`UIR-05` / `UIR-06`）：macOS 正式窗口使用系统 Menubar 和左上原生窗口控件，不能把 Electron 默认菜单视为 LearnLab 菜单已注册；Windows 风格预览保留右上最小化、最大化/还原和关闭三个统一尺寸的占位，不使用多余的 LearnLab 文字替代。LearnLab 不提供独立全屏模式，Bottom Panel 也不提供全屏/最大化入口。标题和实验包上下文避免在相邻行重复。完整菜单点击、窗口排布和真实窗口命令暂缓，具体宿主实现仍按 `UI-08` 逐步确定。

### 2.2 初始尺寸和密度

以下是第一版视觉基线，不要求一次性精确复刻 VSCode，但所有组件应使用统一变量：

```text
Activity Bar：48px
Primary Sidebar：240px ~ 320px，可拖拽调整
Editor Tabs：35px
Bottom Panel：按需展开，初始高度 220px
Status Bar：22px
图标按钮：28px ~ 32px
普通按钮：28px ~ 32px
侧边栏文字：13px
状态栏文字：12px
正文文字：16px ~ 18px
```

中央阅读区使用独立的阅读宽度，例如 760px ~ 920px，并在两侧保留可用空白；工作台的紧凑密度不能牺牲长文阅读体验。

对接后待修的状态与样式规则（`UIR-01` 至 `UIR-04`、`UIR-07`、`UIR-09`）：

- 树行统一缩进、展开位、文字和进度的对齐；区分悬停、键盘焦点、选中及失焦选中。侧栏不重复堆叠同义标题，空/加载/错误状态使用一致的基础字号和内边距。
- 搜索选项的开启状态使用独立底色、前景和边框；键盘焦点另行表达，不能把 focus outline 用作所有开启按钮的常驻边框。输入框内部控件保持间隙，全部开启时仍可辨认各自边界。
- 快速打开使用主题内的圆角、边框和阴影；浮层必须处于同一主题作用域或显式接收主题变量。确认、取消及焦点返回仍需操作验收。
- 以上记录为后续修订目标，精确像素、断点和共享组件方案尚未冻结，本轮不直接修改样式。

### 2.3 功能栏初始入口

Activity Bar 按以下顺序固定核心入口。章节是 LearnLab 的主要驱动；学习区只负责实验包管理、共享依赖和实验包切换，不取代章节入口。

```text
▣ 章节                 当前实验包的章节树和教程入口
⌕ 查找 / 文本搜索和替换 当前文件进入查找模式；跨文件搜索后续开放
◇ 实验                 当前 Markdown 已解析的实验列表与实验历史入口
□ 插件                 已安装、缺失、停用和不兼容插件
⬡ 依赖                 共享依赖、独立运行时和外部前置软件状态
▤ 学习区               当前学习区中的实验包列表，不展开为任意文件树
≡ 文件资源管理器       当前实验包文件视图；普通用户不默认显示整个学习区
```

正式图标目标是 LearnLab 自有 SVG，统一尺寸、线宽、焦点态和悬浮提示。当前搜索入口暂用已署名的 VSCode Codicons 图形，见[第三方版权说明](../THIRD_PARTY_NOTICES.md)；替换之前不能称整套图标均为原创。布局阶段可使用文字或几何占位符。

Activity Bar 底部另保留独立的设置入口，不随上方内容列表滚动；未接入设置页时可使用明确的禁用占位。核心不提供账号和云同步，不影响设置入口的存在。正式 renderer 当前遗漏了原型中的该入口，列为 `UIR-08` 待恢复。

## 3. LearnLab 的工作区模型

### 3.1 实验包视图

主侧边栏默认显示学习结构，而不是把实验包的底层目录完整暴露给普通用户：

```text
实验包：SQL 基础入门
▸ 1 基础查询
  ▸ 1.1 查询入门
    ▸ 1.1.1 SELECT
    ▸ 1.1.2 WHERE
  ▸ 1.2 条件过滤
▸ 2 进阶查询
```

- 章节树按显式层级展示，第一层大章、第二层小节、第三层子节依次嵌套。
- 默认全部折叠；点击箭头只展开/收起，点击章节标题才在中央主窗口加载 Markdown。
- 打开章节后，宿主自动解析该 Markdown 中的实验标记，并刷新“实验”侧边栏。
- 实验包作者应在 manifest 或章节元数据中显式提供章节父子关系；不依赖 `1.1.1` 字符串推断，以支持重排和非数字目录。
- 文件资源管理器默认只显示当前实验包；学习区其他实验包和 `dependencies/` 不通过普通视图暴露。开发者模式可申请更宽的查看范围，但仍受插件/文件权限边界约束。

学习区是一个自包含的本地文件夹：除自身管理文件和共享依赖等内部目录外，内容以实验包目录组织；所有实验包的实际目录都位于学习区内，不通过软连接登记学习区外的实验包，也不设计跨盘联动、断链修复或单个实验包离线状态。

学习区是多个实验包的容器，关系类似 VSCode 的工作区与项目：侧栏可以同时列出多个实验包，但同一时刻只选择一个当前实验包。点击当前已选实验包再次取消选择；点击学习区侧栏的空白区域也回到未选择状态。未选择时不显示实验包专属的章节和文件上下文，不设置额外的“清除当前上下文”按钮。

### 3.2 标签页

教程、实验、笔记、日志和插件视图统一进入标签页系统：

```text
[📖 1.1 查询入门] [🧪 实验 1] [📜 实验历史] [📝 笔记] [×]
```

第一版标签页支持：

- 打开、切换和关闭；
- 当前标签高亮；
- 可关闭与不可关闭标签的区分；
- 同一个实验只打开一个标签，重复点击聚焦已打开标签；
- 实验可以选择作为中央主窗口标签打开，沉浸式实验默认采用此方式；
- 不实现多个 Editor Group；
- 不实现“恢复关闭的标签”，近期打开的文件由 Menubar 提供；
- 章节切换后更新或复用当前教程标签；
- 标签与窗口位置的偏好可以由用户设置保存，但不要求 MVP 恢复完整会话。

### 3.3 中央内容视图

中央工作区至少包含这些视图类型的接口，但可以分阶段实现：

| 视图 | 第一版内容 |
|:---|:---|
| `chapter` | Markdown 教程阅读器 |
| `experiment` | 实验说明和执行入口占位 |
| `note` | Markdown 笔记占位或编辑器入口 |
| `history` | 实验历史只读列表 |
| `plugin` | 插件注册的受控 UI 视图 |

## 4. 插件增强布局

终端、数据库控制台、图表、AI 对话框等不是内核硬编码功能，而是插件提供的视图。

```text
┌──────┬──────────────────┬────────────────────────────────────┐
│功能栏│ 主侧边栏          │ 标签页                             │
│      │                  ├────────────────────────────────────┤
│      │ 章节/实验树       │ 教程阅读区                         │
│      │                  │                                    │
│      │                  ├────────────────────────────────────┤
│      │                  │ 底部面板                             │
│      │                  │ [终端: mysql] [输出] [错误]          │
└──────┴──────────────────┴────────────────────────────────────┘
```

插件面板的显示必须遵守：

- 插件已安装且通过当前实验包依赖解析；
- 插件获得对应的 UI 注册权限；
- 当前包的执行/网络/文件权限仍按独立权限系统判断；
- 插件缺失时显示可解释的提示，教程仍可进入只读阅读模式；
- 插件崩溃不应导致主窗口一起崩溃。

### 4.1 主窗口与辅助侧栏的选择

右侧辅助侧栏不是所有内容的固定归宿，而是一个由用户选择的辅助工作区：

- 视图可以声明推荐位置，但普通视图的最终位置由用户决定：中央主窗口、辅助侧栏或底部面板。
- 实验、沉浸式教程和需要较大操作空间的内容默认进入中央主窗口。
- AI 对话、实时诊断、环境状态等明确的辅助功能默认进入辅助侧栏。
- 辅助侧栏支持标签页、显示/隐藏和宽度调整；MVP 只保留一个辅助侧栏标签组。
- 用户移动视图后的偏好按视图 ID 保存，插件重新加载不能擅自覆盖用户选择。

### 4.2 搜索和替换

“文本搜索和替换”是 Activity Bar 的独立入口，交互参考 VSCode 的搜索视图，但只实现 LearnLab 需要的能力：

- 搜索框支持区分大小写、全字匹配和正则表达式；
- 替换框支持保留大小写和全部替换；
- 搜索框输入后实时更新结果；输入为空时立即清除结果。顶部只保留刷新搜索结果，用于实验包文件被外部修改后的强制重扫，并保留结果排序、折叠/展开等必要操作；
- 实时搜索采用短暂防抖，过期请求不能覆盖最新查询；搜索完成数量和错误在搜索面板内显示，不为每次输入弹出运行时通知；
- 范围入口始终列出 `当前文件`、`当前实验包`、`当前学习区` 三个文字选项，不使用范围图标。选择 `当前文件` 时，Activity Bar 焦点切换到查找模式，只在当前打开教程的单个章节文件内定位匹配，不生成跨文件搜索结果；实验包和学习区范围暂不开放，不扫描学习区外的任意文件；
- 替换前显示影响文件和匹配数量，执行后支持一次撤销；正则错误不能导致应用崩溃，应在搜索视图中显示可读错误。

### 4.3 实验视图与历史

点击“实验”时，主侧边栏显示当前 Markdown 自动解析出的实验标题。点击实验：

1. 若实验标签不存在，则在中央主窗口打开新的实验标签；
2. 若标签已存在，则聚焦该标签；
3. 实验内容底部显示当前实验历史，最新记录优先；
4. 运行输出、具体报错、通过结果和操作细节进入 `experiment_history`，不混入章节阅读百分比；
5. 实验标记解析失败时，Markdown 仍可以阅读；该实验区域显示错误占位，通知宿主并提供可复制的诊断信息。

实验底部历史区域提供“查看全部 / 只看成功 / 只看失败”文字筛选菜单；选项只筛选当前实验的记录，不改变持久化数据。失败记录可展开查看该次执行的错误、输出和步骤。实验侧栏不设独立“诊断”按钮；实验标记解析失败和环境问题分别通过原有错误占位、通知及问题面板呈现，避免把实验结果与软件运行时故障混为一个入口。

实验失败记录必须标明判定来源：手动判定失败显示固定理由“用户判定实验失败”；自动判定失败显示判定器插件返回的理由和分项结果，核心不自行分析或改写插件理由。

插件列表条目默认使用 LearnLab 核心拼图图标；当前插件 manifest 不声明图标，也没有开放插件图标注册 API。未来注册表接入后，只有通过注册校验的插件图标才可替换该默认图标，不能覆盖核心 Activity Bar 图标。

插件更新入口沿用 VSCode 的文字按钮形式：侧栏条目显示“更新”，详情页可显示“更新到版本号”。右键菜单需要图标时，`ICON-PLUGIN-15` 复用安装/下载的 `actions/dependency-download.svg`；版本变化由文字说明，不新增向上箭头。该复用范围已确认，安装、升级兼容性与版本来源接线后续实现。

右侧辅助栏是插件可以注册的受控 UI 位置之一。AI 对话只是插件的一种示例：AI 插件可以只注册右侧辅助栏，标题、对话内容、上下文、输入输出、操作和内部图标全部由插件自行组织。LearnLab 核心只提供宿主容器、位置、主题/尺寸约束、可访问性和生命周期，不为 AI 或其他插件领域预先设计专用图标。插件也可以按受控注册能力使用其他允许的位置；右侧辅助栏不是 AI 功能的核心内建入口。

学习区实验包列表行左侧显示实验包身份图标。默认使用 LearnLab 的包装盒图标；作者可以为自己的实验包注册包内图标，通过宿主校验后优先显示。作者资源不能覆盖核心 Activity Bar 图标、其他包或文件类型图标。缺失、无效或加载失败时回退默认图标，不影响列表与章节阅读，并保留可诊断原因。当前 manifest 和正式列表尚无作者图标字段与加载接线；字段、资源格式与安全加载方案在后续实现阶段设计，本轮仅确定显示与回退规则。

依赖列表中的每个依赖条目默认使用单个软件包图标 `ICON-DEPENDENCY-01`。如果依赖自身注册了通过宿主校验的图标，则优先显示该注册图标；实验包 `bundled-dependencies/` 附带的依赖与依赖仓库下载的依赖使用相同规则。依赖来源、共享关系和异常不通过另画一套主体图标表达，分别由文字、属性信息和通用状态图标表达。当前依赖注册字段、资源校验和 renderer 加载接线尚未实现。

插件列表不使用独立的“已启用/已禁用”状态图标。当前活动解析结果中的插件保持正常对比度；用户禁用（配置 `enabled: false`）或未被当前实验包选中的已安装插件，在列表中统一作为“当前未启用”灰化图标、名称和次要文字，同时保持可读性与清楚的选中轮廓。按需延迟启动不等于未启用；只有预期应加载却失败等异常才显示异常状态和原因。底层仍区分用户禁用、未选中、缺失、阻塞和不兼容，不能仅凭加载进程数或插件作用范围推断状态。正式列表目前只接收插件 manifest，状态接线留待活动解析结果进入 renderer。

缺失、版本不兼容和加载失败等具体原因统一归为异常状态；列表保留原因文字及底层结果，图标按严重级别复用。一般异常显示黄色感叹号，`Error`/`Fatal` 显示红色感叹号；`Fatal` 仍使用独立错误窗口及隔离流程。这里的异常是 UI 分类，不改变现有业务结果的返回方式。已安装但当前未启用的灰色状态不是异常。

Markdown 内嵌实验卡片的“打开实验”是文字按钮，只负责打开或聚焦实验标签，不直接启动实验程序，不使用播放图标。实验标签内真正执行命令时才使用播放图标。核心 UI 不维护或展示全局“实验运行中”状态，也不为此设计旋转图标；执行监督器仍需跟踪本实验启动的进程，以便超时和关闭标签时清理。实验页不设独立“停止”或“刷新”按钮；“重置”保留并复用通用刷新图标，不为小实验重置增加风险确认。

关闭实验标签前，宿主检查该实验启动的程序及其专用依赖进程是否全部退出。仍有存活进程时弹出确认对话框，提供“强制退出”与“取消”；取消则保留标签，确认后由执行监督器回收进程树，确认已退出后才关闭标签。学习区共享依赖或其他实验的进程不能因关闭此标签而被结束。检查或清理失败时保留标签并显示可处理的错误，不能静默遗留进程。

现行实现使用系统确认框，默认选中“取消”。切换实验包会关闭旧包标签，因此同样触发检查。打开其他标签仍可保留实验的输出和当前运行状态。

## 5. 主题、颜色和图标

### 5.1 主题变量

主题通过 CSS 变量实现，主题插件只提供经过宿主校验的变量，不直接覆盖应用结构：

```css
:root {
  --ll-activity-bg: #202020;
  --ll-sidebar-bg: #252526;
  --ll-editor-bg: #1e1e1e;
  --ll-panel-bg: #252526;
  --ll-border: #3e3e42;
  --ll-text: #cccccc;
  --ll-muted-text: #858585;
  --ll-accent: #3794ff;
  --ll-active-bg: #37373d;
  --ll-danger: #f14c4c;
  --ll-warning: #cca700;
  --ll-success: #89d185;
}
```

必须同时预留浅色主题变量，但 MVP 可以先实现一个深色主题和一个浅色主题的静态基线。

### 5.2 状态和交互

所有交互组件至少定义：

- 默认态；
- 悬浮态；
- 激活态；
- 键盘焦点态；
- 禁用态；
- 加载态；
- 错误和警告态。

颜色不能是组件内散落的硬编码值。主题变量和组件语义状态必须分离。

通用加载态采用 `common/loading.svg` 四分之三圆弧：16px、半径 `5.5`、线宽 `1.2`，默认每秒匀速旋转一圈。教程读取、文件列表刷新和插件安装/更新操作共用，旁边始终保留具体状态文字；已有列表可继续展示，不用加载圆环替换资源主体图标。系统减少动态效果时停止旋转，保留静态图形和文字。未知进度不显示百分比，不用于实验运行中或插件是否启用的状态。图形与动画规范已确认，正式组件接线后续实现。

菜单当前项和布尔设置复选框复用已有对勾几何（`ICON-MENU-02`，沿用 `common/completed.svg` 路径及 `1.45` 线宽）。菜单选中位使用菜单文字色，未选中时保留空位；设置复选框使用主题选中色底框及对应前景色对勾。实验历史筛选的当前项沿用同一标记。选中语义与绿色完成/成功反馈分开，不因此为插件条目新增启用徽标。图形与复用范围已确认，正式控件接线后续实现。

设置窗口的分类栏使用文字导航，常规、外观、快捷键不新增分类专用图标；设置入口和标签保留已有齿轮。插件注册设置项时，左侧分类栏显示该插件的名称，使用户可按插件名称访问对应设置。此处是已确认的功能显示要求；插件设置注册接口、实际分组与加载接线尚未实现，不把预览当作已开放的注册能力。

未保存修改使用 `ICON-TAB-05`：标签右侧 6px 实心圆点，继承标签文字色，与关闭叉号共用 24px 指示区，悬停显示关闭叉号而不改变标签宽度。可编辑文档内容或显式保存的设置草稿不同于保存快照时显示，保存或恢复后消失；只读教程阅读进度及即时生效设置不触发。图形和复用范围已确认，正式组件接线与设置保存策略另行实现。

当前学习区使用标题名称及已有身份图标，当前实验包使用已有包图标及列表行选中，不新增勾选文件夹或实心包状态图。空列表、无实验和需要用户操作的状态使用具体文字，例如“暂无实验历史”“当前章节没有实验”“请先选择一个实验包”，不加入空盒子、烧杯空标记或手形提示图。这五个独立状态图标的剔除方案已确认；选择、空状态与引导逻辑仍保留，真实异常继续使用对应异常等级图标。

## 6. 学习内容视图

### 6.1 阅读模式

Markdown 阅读器是中央工作区的第一个正式视图，支持：

- 标题、段落、列表、代码块；
- Front Matter 提供的章节元数据；
- 章节内目录跳转；
- 代码复制；
- 逐步加载和明确错误；
- 未来由插件提供公式、图表、交互容器。

教程正文采用适合阅读的排版，不强行模拟代码编辑器。代码块可以使用工作台主题变量，但需要保留长代码的横向滚动。

### 6.2 实验模式

实验卡片或实验视图可以包含：

- 实验目标；
- 前置条件；
- 卡片中的“打开实验”、实验标签内的执行和重置；关闭标签时处理专用进程退出；
- 提示和答案；
- 运行输出；
- 分项判定反馈。

实验执行能力由插件决定，UI 只负责统一承载状态和操作，不把 MySQL 或其他环境写死在核心阅读器中。

### 6.3 视频模式

视频是可选的内容视图，不是所有实验包的默认内容：

- 支持实验包声明的视频资源；
- 视频视图可以作为标签页或分屏视图打开；
- 进度记录与文本阅读进度分开；
- 视频时间戳笔记联动属于后续功能。

## 7. 进度、搜索和笔记

### 7.1 进度显示

- 文本章节进度由滚动位置计算；
- 滚动到底视为完成；
- 实验操作不影响文本阅读完成度；
- 看过答案后通过不需要额外标记；
- 新增章节不重置未改动章节；
- 内容发生变化的章节，按内容指纹重置为 0%；
- 实验细节、报错和通过情况进入实验历史，不塞进阅读百分比。

状态栏核心保留项为：

```text
左侧：当前文档阅读进度 100% · 已加载插件 3 个
中间：插件注册的状态项
右侧：未预览消息 2
```

不显示“章节 2/8”这类章节计数。左、中、右三个区域都允许插件注册状态项；核心只占用当前文档进度、已加载插件数量和未预览消息这三个语义位置。

### 7.2 全局搜索

查找与文本搜索和替换共用 Activity Bar 的放大镜入口。范围始终以 `当前文件`、`当前实验包`、`当前学习区` 三个文字选项表达，不使用单独的范围图标；MVP 只开放当前文件查找：

- 选择当前文件时，Activity Bar 焦点转到查找模式；只在当前打开的教程章节文件中定位并高亮匹配，提供上一个/下一个匹配，不打开结果标签；
- 后续实验包或学习区范围的跨文件结果打开独立选项卡；相同搜索目标应聚焦既有结果标签，不重复创建；
- 实验包和学习区范围暂不开放，不直接扫描学习区外的文件；
- 搜索索引可以先采用遍历，规模变大后再引入索引；
- 替换操作只作用于当前允许的范围，并在执行前显示影响文件与匹配数量。

### 7.3 运行时通知（独立于日志）

通知用于软件、插件、依赖、实验包等运行时事件；日志用于诊断和历史记录，两者不互相替代。

- `info` 使用主题正常色；`warning` 使用黄色；`error` 使用红色；
- 通知以右下角气泡显示，可包含标题、正文、来源和操作按钮；
- 可自动消失的通知在顶部显示与等级一致的窄亮条作为消失进度条；进度条走满后约 1 秒通知消失；
- 所有 `info` 从各自创建时间起独立显示 7 秒进度条，进度结束后约 1 秒自动消失；`warning` 和 `error` 默认保留到用户关闭或完成处理；
- 重复通知按来源、等级和消息指纹进行合并，避免插件循环刷屏；
- 通知中心/未预览消息数量由状态栏右侧入口打开，查看后清除未预览状态，但不删除日志。
- 通知中心列表的 `info`、`warning`、`error` 统一使用带圆圈的小写 `i` 图形（复用 `actions/info.svg`，16px），分别显示主题蓝、黄、红色；颜色由通知等级指定，不为三个等级维护三份图形资源。该规则对应通知中心预览场景 2，其他场景沿用其已确认规格。
- 常规运行时事件默认复用上述通知结构、对应等级的通用图标和通知中心；不为每个事件另造专用卡片或对话框。确需阻断当前操作或已有明确确认要求的特殊流程，才使用对话框。
- 插件权限请求属于 `info` 通知，复用通用蓝色 `i` 图标、标题、正文、右上角关闭和顶部进度条，不使用独立权限图标或确认对话框；正文列出插件、作用域和请求范围。操作区提供“拒绝”和“允许”菜单，菜单内为“单次允许”“始终允许”。通知沿用 `info` 的独立 7 秒进度条与约 1 秒后的自动收起规则，收起后待处理请求仍在通知中心；关闭气泡、查看通知中心或计时结束都不授予或拒绝权限。打开通知中心只清除未查看计数，不清除待处理请求。待处理请求不能被普通的清空通知操作移除；单次允许仅用于当前启动。始终允许匹配当前实验包、插件安装和权限组合。关闭实验标签或切换实验包会撤回对应请求。

`fatal` 不作为普通气泡处理。主进程确认应用无法继续正常运行后，立即停止普通窗口交互、关闭其他应用窗口，只保留专用错误展示进程/窗口和错误对话框 UI；同时写入本地脱敏报告。Fatal 窗口固定显示同一组文字操作，顺序为“复制错误报告”“重新启动 LearnLab”“退出”，不为复制或重启另造图标；用户确认只用于复制报告、重新启动或完成最终退出。若错误展示 UI 自身无法创建，则退回系统原生错误对话框后退出。

### 7.4 笔记

笔记正文使用普通 Markdown 文件，元数据可存数据库：

```text
~/.learnlab/notes/
├── packages/
│   └── sql-intro/
├── free/
└── tags/
```

核心不内置云同步。用户可以复制 Markdown、导出设置 JSON，或通过插件接入自己的同步方案。

笔记可以作为独立标签页打开，也可以与教程做分屏布局。分屏和视频时间戳联动属于后续阶段。

| Titlebar / Command Center | 应用内标题区和命令入口 | 当前上下文、快速打开和命令，不复制完整 Menubar |
| Activity Bar | 章节、搜索替换、实验、插件、依赖、学习区、文件资源管理器 | 一级功能切换，使用自有图标 |
| Primary Sidebar | 实验包/章节/实验导航或当前功能面板 | 显示学习结构，而不是默认显示文件树 |
| Editor Tabs | 教程/实验/笔记/日志标签 | 只有一个主 Editor Group |
| Editor Area | 学习与实验主工作区 | 正文适合阅读，实验由插件提供 |
| Auxiliary Sidebar | AI、诊断和用户选择的辅助视图 | 支持标签；普通视图可由用户选择位置 |
| Bottom Panel | 终端、输出、诊断和实验历史 | 仅在需要时展开 |
| Status Bar | 当前文档进度、已加载插件、未预览消息和插件项 | 左/中/右槽位均可由插件注册 |
| Notification Host | 右下角运行时通知气泡 | 独立于日志；fatal 由主进程特殊处理 |
| Command Palette | LearnLab 命令入口 | 核心和插件统一注册命令 |
| Theme variables | LearnLab 主题系统 | 参考信息层级，不复制品牌资产 |

最终目标是：用户看到 LearnLab 时，能获得类似 VSCode 的稳定、优雅、可扩展的工作台体验；但用户学习的对象是实验包，而不是源代码项目。
