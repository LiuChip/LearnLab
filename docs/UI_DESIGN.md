# UI 设计

> 相关文档：[总览](OVERVIEW.md) · [架构设计](ARCHITECTURE.md) · [项目结构](PROJECT_STRUCTURE.md)
>
> **正式决策（2026-09-02）**：LearnLab 的桌面 UI 直接以 VSCode Workbench 作为主要对标对象。对标范围包括布局、面板组织、标签页、命令入口、状态栏、主题变量和交互密度；图标、品牌、文案和学习内容模型使用 LearnLab 自己的设计。

---

## 1. 设计目标与边界

LearnLab 不是普通的 Markdown 网页阅读器，而是一个**以学习内容为中心、可由插件扩展的本地学习工作台**。

UI 设计目标按优先级排列：

1. 直接采用成熟的 Workbench 空间组织方式，降低复杂功能加入后的重构成本。
2. 让第一次使用的用户能够清楚地区分实验包、章节、实验、日志、插件和运行环境。
3. 保持中央教程内容适合长文阅读，不把所有内容强行做成代码编辑器。
4. 让插件可以在受控权限下注册面板、命令、按钮、标签页和状态栏项目。
5. 先实现静态且可测试的 UI 壳，再接入数据库、插件执行和实验运行时。

### 不做的事情

- 不复制 VSCode 的品牌、图标资源、欢迎页文案或产品名称。
- 不因为外观对标 VSCode 就强制实现 Git、调试器、远程开发等 LearnLab 不需要的功能。
- 不让插件直接向 DOM 注入任意页面；插件 UI 必须通过宿主定义的视图注册接口接入。
- 不把阅读进度、实验历史和插件设置混在 UI 状态中；持久化边界由数据模型文档决定。

## 2. 正式 Workbench 布局

### 2.1 默认窗口结构

LearnLab 默认采用 VSCode 风格的 Workbench，而不是旧的“简单两栏”布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部标题区 / 菜单 / 命令入口 / 搜索 / 布局操作                 │
├──────┬──────────────────┬────────────────────────────────────┤
│      │                  │ 编辑器标签页                         │
│      │                  ├────────────────────────────────────┤
│功能栏│   主侧边栏        │                                    │
│      │                  │          中央工作区                  │
│      │   实验包导航      │  教程 / 实验 / 笔记 / 插件视图        │
│      │   章节目录        │                                    │
│      │   当前功能面板    │                                    │
├──────┴──────────────────┴────────────────────────────────────┤
│ 底部面板（按需打开：终端 / 输出 / 日志 / 错误）                 │
├──────────────────────────────────────────────────────────────┤
│ 状态栏：进度 / 环境 / 依赖 / 插件状态                           │
└──────────────────────────────────────────────────────────────┘
```

布局区域的职责：

| 区域 | 默认职责 | 插件是否可扩展 |
|:---|:---|:---:|
| 顶部标题区 | 当前学习区、当前实验包、搜索、命令和窗口级操作 | 可注册命令和操作，不直接改写窗口框架 |
| 功能栏 Activity Bar | 切换实验包、搜索、插件、依赖、设置等一级功能 | 可以注册新的受控入口 |
| 主侧边栏 Primary Sidebar | 当前功能的树、列表、筛选器和摘要 | 可以注册侧边栏视图 |
| 编辑器标签页 Editor Tabs | 教程、实验、笔记、日志、插件视图 | 可以注册标签页类型 |
| 中央工作区 Editor Area | 当前主要学习或实验内容 | 可以注册内容视图 |
| 底部面板 Bottom Panel | 终端、输出、诊断、实验日志等高密度信息 | 只能通过面板 API 注册 |
| 状态栏 Status Bar | 全局低干扰状态信息 | 可以注册状态项，但必须受权限和数量限制 |

### 2.2 初始尺寸和密度

以下是第一版视觉基线，不要求一次性精确复刻 VSCode，但所有组件应使用统一变量：

```text
Activity Bar：48px
Primary Sidebar：240px ~ 320px，可拖拽调整
Editor Tabs：35px
Bottom Panel：按需展开，初始高度 220px
Status Bar：22px
图标按钮：28px ~ 32px
普通按钮：28px ~ 32px
侧边栏文字：13px
状态栏文字：12px
正文文字：16px ~ 18px
```

中央阅读区使用独立的阅读宽度，例如 760px ~ 920px，并在两侧保留可用空白；工作台的紧凑密度不能牺牲长文阅读体验。

### 2.3 功能栏初始入口

第一版不追求大量入口，只固定以下功能：

```text
📚 实验包       当前学习区、实验包和章节
🔍 搜索         当前学习区全文搜索
🧩 插件         已安装插件、缺失插件和插件状态
📦 依赖         运行时依赖和外部前置软件状态
⚙ 设置         LearnLab 和插件设置
```

图标使用 LearnLab 自己设计的 SVG 图标，统一尺寸、线宽、焦点态和悬浮提示。不得直接依赖 VSCode 的图标字体或品牌资源。

## 3. LearnLab 的工作区模型

### 3.1 实验包视图

主侧边栏默认显示学习结构，而不是把实验包的底层目录完整暴露给普通用户：

```text
实验包：SQL 基础入门
├── 📖 教程
│   ├── 01 基础查询       100%
│   └── 02 条件过滤        35%
├── 🧪 实验
│   └── 实验 1：查询 users 表
├── 📝 笔记
├── 📜 实验历史
└── 📁 资源（开发者模式）
```

开发者模式可以增加“文件视图”，但普通学习视图不应被文件层级干扰。

### 3.2 标签页

教程、实验、笔记、日志和插件视图统一进入标签页系统：

```text
[📖 基础查询] [🧪 实验 1] [📜 实验日志] [📝 笔记] [×]
```

第一版标签页只需要支持：

- 打开和切换；
- 当前标签高亮；
- 可关闭与不可关闭标签的区分；
- 章节切换后更新当前教程标签；
- 最小的内存状态，不立即实现复杂恢复。

### 3.3 中央内容视图

中央工作区至少包含这些视图类型的接口，但可以分阶段实现：

| 视图 | 第一版内容 |
|:---|:---|
| `chapter` | Markdown 教程阅读器 |
| `experiment` | 实验说明和执行入口占位 |
| `note` | Markdown 笔记占位或编辑器入口 |
| `history` | 实验历史只读列表 |
| `plugin` | 插件注册的受控 UI 视图 |

## 4. 插件增强布局

终端、数据库控制台、图表、AI 对话框等不是内核硬编码功能，而是插件提供的视图。

```text
┌──────┬──────────────────┬────────────────────────────────────┐
│功能栏│ 主侧边栏          │ 标签页                             │
│      │                  ├────────────────────────────────────┤
│      │ 章节/实验树       │ 教程阅读区                         │
│      │                  │                                    │
│      │                  ├────────────────────────────────────┤
│      │                  │ 底部面板                             │
│      │                  │ [终端: mysql] [输出] [错误]          │
└──────┴──────────────────┴────────────────────────────────────┘
```

插件面板的显示必须遵守：

- 插件已安装且通过当前实验包依赖解析；
- 插件获得对应的 UI 注册权限；
- 当前包的执行/网络/文件权限仍按独立权限系统判断；
- 插件缺失时显示可解释的提示，教程仍可进入只读阅读模式；
- 插件崩溃不应导致主窗口一起崩溃。

## 5. 主题、颜色和图标

### 5.1 主题变量

主题通过 CSS 变量实现，主题插件只提供经过宿主校验的变量，不直接覆盖应用结构：

```css
:root {
  --ll-activity-bg: #202020;
  --ll-sidebar-bg: #252526;
  --ll-editor-bg: #1e1e1e;
  --ll-panel-bg: #252526;
  --ll-border: #3e3e42;
  --ll-text: #cccccc;
  --ll-muted-text: #858585;
  --ll-accent: #3794ff;
  --ll-active-bg: #37373d;
  --ll-danger: #f14c4c;
  --ll-warning: #cca700;
  --ll-success: #89d185;
}
```

必须同时预留浅色主题变量，但 MVP 可以先实现一个深色主题和一个浅色主题的静态基线。

### 5.2 状态和交互

所有交互组件至少定义：

- 默认态；
- 悬浮态；
- 激活态；
- 键盘焦点态；
- 禁用态；
- 加载态；
- 错误和警告态。

颜色不能是组件内散落的硬编码值。主题变量和组件语义状态必须分离。

## 6. 学习内容视图

### 6.1 阅读模式

Markdown 阅读器是中央工作区的第一个正式视图，支持：

- 标题、段落、列表、代码块；
- Front Matter 提供的章节元数据；
- 章节内目录跳转；
- 代码复制；
- 逐步加载和明确错误；
- 未来由插件提供公式、图表、交互容器。

教程正文采用适合阅读的排版，不强行模拟代码编辑器。代码块可以使用工作台主题变量，但需要保留长代码的横向滚动。

### 6.2 实验模式

实验卡片或实验视图可以包含：

- 实验目标；
- 前置条件；
- 开始、停止、重置；
- 提示和答案；
- 运行输出；
- 分项判定反馈。

实验执行能力由插件决定，UI 只负责统一承载状态和操作，不把 MySQL 或其他环境写死在核心阅读器中。

### 6.3 视频模式

视频是可选的内容视图，不是所有实验包的默认内容：

- 支持实验包声明的视频资源；
- 视频视图可以作为标签页或分屏视图打开；
- 进度记录与文本阅读进度分开；
- 视频时间戳笔记联动属于后续功能。

## 7. 进度、搜索和笔记

### 7.1 进度显示

- 文本章节进度由滚动位置计算；
- 滚动到底视为完成；
- 实验操作不影响文本阅读完成度；
- 看过答案后通过不需要额外标记；
- 新增章节不重置未改动章节；
- 内容发生变化的章节，按内容指纹重置为 0%；
- 实验细节、报错和通过情况进入实验历史，不塞进阅读百分比。

状态栏可以显示：

```text
章节 1 / 2 · 阅读进度 100% · 实验环境 未启动 · 插件 3 个已加载
```

### 7.2 全局搜索

全局搜索是 Activity Bar 的一级入口，第一版范围为当前学习区：

- 搜索实验包名称、章节标题和正文纯文本；
- 返回实验包、章节、匹配片段和跳转位置；
- 不直接扫描学习区外的文件；
- 搜索索引可以先采用遍历，规模变大后再引入索引。

### 7.3 笔记

笔记正文使用普通 Markdown 文件，元数据可存数据库：

```text
~/.learnlab/notes/
├── packages/
│   └── sql-intro/
├── free/
└── tags/
```

核心不内置云同步。用户可以复制 Markdown、导出设置 JSON，或通过插件接入自己的同步方案。

笔记可以作为独立标签页打开，也可以与教程做分屏布局。分屏和视频时间戳联动属于后续阶段。

## 8. 面板排列和响应式规则

### 8.1 默认单列

中央工作区默认一次显示一个主视图：

```text
[教程标签]
────────────────────────
        教程内容
────────────────────────
```

### 8.2 分屏

当用户打开笔记、实验或插件视图时，可以使用双列或上下分屏：

```text
┌──────────────────────┬──────────────────────┐
│ 教程                  │ 实验 / 笔记 / AI      │
└──────────────────────┴──────────────────────┘
```

### 8.3 小窗口规则

窗口宽度不足时按以下顺序收缩：

1. 隐藏非必要的辅助文字，只保留图标和 tooltip；
2. 收窄主侧边栏；
3. 把底部面板改为覆盖式或折叠式；
4. 保证中央教程仍能阅读；
5. 不让插件视图突破宿主边界。

## 9. 与 VSCode 的关系

这是**直接对标**，不是只在插件增强模式下才相似：

| VSCode Workbench | LearnLab | 说明 |
|:---|:---|:---|
| Activity Bar | LearnLab 功能栏 | 一级功能切换，使用自有图标 |
| Primary Sidebar | 实验包/章节/实验导航 | 显示学习结构，而不是默认显示文件树 |
| Editor Tabs | 教程/实验/笔记/日志标签 | 统一承载可打开内容 |
| Editor Area | 学习与实验主工作区 | 正文适合阅读，实验由插件提供 |
| Auxiliary/Bottom Panel | 终端、输出、诊断、AI | 仅在需要时展开 |
| Status Bar | 学习进度、依赖和环境状态 | 低干扰展示全局信息 |
| Command Palette | LearnLab 命令面板 | 核心和插件统一注册命令 |
| Theme variables | LearnLab 主题系统 | 参考信息层级，不复制品牌资产 |

最终目标是：用户看到 LearnLab 时，能获得类似 VSCode 的稳定、优雅、可扩展的工作台体验；但用户学习的对象是实验包，而不是源代码项目。
