> 相关文档：[总览](OVERVIEW.md) · [架构设计](ARCHITECTURE.md) · [项目结构](PROJECT_STRUCTURE.md) · [未冻结决策清单](../UNFREEZE.md)
>
> **正式决策（2026-09-04）**：LearnLab 的桌面 UI 直接以 VSCode Workbench 作为主要对标对象。对标范围包括布局、面板组织、标签页、命令入口、状态栏、通知和交互密度；图标、品牌、文案和学习内容模型使用 LearnLab 自己的设计。顶部原生 Menubar、应用内命令入口、主侧边栏、中央主窗口、可选辅助侧栏和底部面板都属于正式布局；图标最后实现，前期使用占位符。

### UI 冻结边界

当前已经冻结的是 Workbench 的区域组成、Activity Bar 的一级功能、章节树的交互、单一 Editor Group、不恢复关闭标签、AI 等辅助视图默认进入右侧辅助侧栏、状态栏核心信息、通知等级/位置/消失提示以及 Fatal 隔离行为。

仍未冻结的是各区域精确尺寸和响应式断点、普通视图的默认落点和记忆方式、标签页的预览/固定/脏状态、搜索结果和替换确认的全部细节、通知堆叠与历史、快捷键默认值、UI 原型与正式 renderer 的长期边界，以及正式图标和最终视觉细节。实现这些部分时以 [UNFREEZE.md](../UNFREEZE.md) 的 `UI-*` 条目为准。

## 1. 设计目标与边界

LearnLab 不是普通的 Markdown 网页阅读器，而是一个**以学习内容为中心、可由插件扩展的本地学习工作台**。

UI 设计目标按优先级排列：

1. 直接采用成熟的 Workbench 空间组织方式，降低复杂功能加入后的重构成本。
2. 让第一次使用的用户能够清楚地区分实验包、章节、实验、日志、插件和运行环境。
3. 保持中央教程内容适合长文阅读，不把所有内容强行做成代码编辑器。
4. 让插件可以在受控权限下注册面板、命令、按钮、标签页和状态栏项目。
5. 先实现静态且可测试的 UI 壳，再接入数据库、插件执行和实验运行时。

### 不做的事情

- 不复制 VSCode 的品牌、图标资源、欢迎页文案或产品名称。
- 不因为外观对标 VSCode 就强制实现 Git、调试器、远程开发等 LearnLab 不需要的功能。
- 不让插件直接向 DOM 注入任意页面；插件 UI 必须通过宿主定义的视图注册接口接入。
- 不把阅读进度、实验历史和插件设置混在 UI 状态中；持久化边界由数据模型文档决定。

## 2. 正式 Workbench 布局

### 2.1 默认窗口结构

LearnLab 默认采用 VSCode 风格的 Workbench，而不是旧的“简单两栏”布局。顶部需要区分操作系统原生菜单和应用内标题/命令区域：macOS 的菜单由系统 Menubar 承载，Windows/Linux 则在应用窗口顶部显示 Menubar；两者的菜单命令保持一致。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 原生 Menubar：文件 / 编辑 / 查看 / 转到 / 运行 / 窗口 / 帮助          │
├────────────────────────────────────────────────────────────────────┤
│ 应用内标题区：返回前进 · 当前学习区/实验包 · 命令入口/快速打开 · 布局 │
├──────┬──────────────────────┬──────────────────┬────────────────────┤
│      │                      │ 编辑器标签页     │                    │
│      │                      ├──────────────────┤                    │
│功能栏│    主侧边栏          │                  │  辅助侧栏（可选）  │
│      │    当前功能视图      │  中央主窗口       │  AI / 插件辅助视图  │
│      │                      │  教程 / 实验      │  可切换标签         │
│      │                      │  笔记 / 插件      │                    │
├──────┴──────────────────────┴──────────────────┴────────────────────┤
│ 底部面板（按需：终端 / 输出 / 日志 / 错误 / 实验历史）                │
├────────────────────────────────────────────────────────────────────┤
│ 状态栏：核心阅读进度/已加载插件 + 插件可注册的左/中/右状态项          │
└────────────────────────────────────────────────────────────────────┘
```

布局区域的职责：

| 区域 | 默认职责 | 插件是否可扩展 |
|:---|:---|:---:|
| 原生 Menubar | 文件、编辑、查看、转到、运行、窗口、帮助、近期打开文件和窗口级命令 | 插件只能注册受控命令/菜单项，不能改写原生菜单结构 |
| 应用内标题区 / Command Center | 返回前进、当前学习区/实验包上下文、快速打开/命令入口和布局操作 | 可注册命令和操作，不直接改写窗口框架 |
| 功能栏 Activity Bar | 切换章节、搜索和替换、实验、插件、依赖、学习区、文件资源管理器 | 可以注册新的受控入口，但 MVP 先固定核心入口 |
| 主侧边栏 Primary Sidebar | 当前功能的树、列表、筛选器和摘要 | 可以注册受控侧边栏视图 |
| 编辑器标签页 Editor Tabs | 教程、实验、笔记、日志和插件视图 | 可以注册标签页类型，但不支持多 Editor Group |
| 中央主窗口 Editor Area | 用户当前的主要学习或实验内容 | 可以注册受控内容视图 |
| 辅助侧栏 Auxiliary Sidebar | 用户选择的辅助视图；AI 等明确的辅助插件默认固定在此 | 可由插件注册标签；普通视图允许用户选择主窗口或辅助侧栏 |
| 底部面板 Bottom Panel | 终端、输出、诊断、实验日志和当前实验历史等高密度信息 | 只能通过面板 API 注册 |
| 状态栏 Status Bar | 当前文档阅读进度、已加载插件数量、未预览消息和插件状态项 | 插件可在左/中/右槽位注册状态项，受权限和数量限制 |
| 通知宿主 Notification Host | 右下角运行时消息气泡；与日志内容分离 | 插件可提交结构化通知，但等级和生命周期由宿主控制 |

**窗口放置规则**：视图注册协议提供 `preferredLocation: main | auxiliary | bottom` 和 `userCanMove`。实验视图默认在中央主窗口打开，用户可将适合辅助阅读的视图移到辅助侧栏；AI 对话、实时诊断等明确的辅助插件默认在辅助侧栏。MVP 不支持多个 Editor Group，但辅助侧栏拥有独立标签组。

### 2.1.1 原生 Menubar 与应用内命令入口

- Menubar 是跨平台正式功能，不因 macOS 将菜单绘制在系统顶部而省略；Electron 主进程统一创建菜单模板。
- Menubar 负责稳定的全局操作：打开/切换学习区、近期打开文件、关闭标签、设置、退出、帮助和开发者操作。
- 应用内标题区负责当前上下文和快速操作，不复制全部 Menubar；命令入口可搜索核心命令和插件命令。
- 菜单命令必须拥有稳定的 command ID，后续快捷键和插件注册都引用 command ID，而不是依赖显示文本。
- 具体菜单文案、快捷键和正式图标属于后续实现细节；布局骨架阶段可先使用文字占位。

### 2.2 初始尺寸和密度

以下是第一版视觉基线，不要求一次性精确复刻 VSCode，但所有组件应使用统一变量：

```text
Activity Bar：48px
Primary Sidebar：240px ~ 320px，可拖拽调整
Editor Tabs：35px
Bottom Panel：按需展开，初始高度 220px
Status Bar：22px
图标按钮：28px ~ 32px
普通按钮：28px ~ 32px
侧边栏文字：13px
状态栏文字：12px
正文文字：16px ~ 18px
```

中央阅读区使用独立的阅读宽度，例如 760px ~ 920px，并在两侧保留可用空白；工作台的紧凑密度不能牺牲长文阅读体验。

### 2.3 功能栏初始入口

Activity Bar 按以下顺序固定核心入口。章节是 LearnLab 的主要驱动；学习区只负责实验包管理、共享依赖和实验包切换，不取代章节入口。

```text
▣ 章节                 当前实验包的章节树和教程入口
⌕ 文本搜索和替换       当前范围内搜索，支持大小写、全字匹配和正则
◇ 实验                 当前 Markdown 已解析的实验列表与实验历史入口
□ 插件                 已安装、缺失、停用和不兼容插件
⬡ 依赖                 共享依赖、独立运行时和外部前置软件状态
▤ 学习区               当前学习区中的实验包列表，不展开为任意文件树
≡ 文件资源管理器       当前实验包文件视图；普通用户不默认显示整个学习区
```

图标使用 LearnLab 自己设计的 SVG 图标，统一尺寸、线宽、焦点态和悬浮提示。布局阶段使用文字或几何占位符，不直接依赖 VSCode 的图标字体或品牌资源。

## 3. LearnLab 的工作区模型

### 3.1 实验包视图

主侧边栏默认显示学习结构，而不是把实验包的底层目录完整暴露给普通用户：

```text
实验包：SQL 基础入门
▸ 1 基础查询
  ▸ 1.1 查询入门
    ▸ 1.1.1 SELECT
    ▸ 1.1.2 WHERE
  ▸ 1.2 条件过滤
▸ 2 进阶查询
```

- 章节树按显式层级展示，第一层大章、第二层小节、第三层子节依次嵌套。
- 默认全部折叠；点击箭头只展开/收起，点击章节标题才在中央主窗口加载 Markdown。
- 打开章节后，宿主自动解析该 Markdown 中的实验标记，并刷新“实验”侧边栏。
- 实验包作者应在 manifest 或章节元数据中显式提供章节父子关系；不依赖 `1.1.1` 字符串推断，以支持重排和非数字目录。
- 文件资源管理器默认只显示当前实验包；学习区其他实验包和 `dependencies/` 不通过普通视图暴露。开发者模式可申请更宽的查看范围，但仍受插件/文件权限边界约束。

### 3.2 标签页

教程、实验、笔记、日志和插件视图统一进入标签页系统：

```text
[📖 1.1 查询入门] [🧪 实验 1] [📜 实验历史] [📝 笔记] [×]
```

第一版标签页支持：

- 打开、切换和关闭；
- 当前标签高亮；
- 可关闭与不可关闭标签的区分；
- 同一个实验只打开一个标签，重复点击聚焦已打开标签；
- 实验可以选择作为中央主窗口标签打开，沉浸式实验默认采用此方式；
- 不实现多个 Editor Group；
- 不实现“恢复关闭的标签”，近期打开的文件由 Menubar 提供；
- 章节切换后更新或复用当前教程标签；
- 标签与窗口位置的偏好可以由用户设置保存，但不要求 MVP 恢复完整会话。

### 3.3 中央内容视图

中央工作区至少包含这些视图类型的接口，但可以分阶段实现：

| 视图 | 第一版内容 |
|:---|:---|
| `chapter` | Markdown 教程阅读器 |
| `experiment` | 实验说明和执行入口占位 |
| `note` | Markdown 笔记占位或编辑器入口 |
| `history` | 实验历史只读列表 |
| `plugin` | 插件注册的受控 UI 视图 |

## 4. 插件增强布局

终端、数据库控制台、图表、AI 对话框等不是内核硬编码功能，而是插件提供的视图。

```text
┌──────┬──────────────────┬────────────────────────────────────┐
│功能栏│ 主侧边栏          │ 标签页                             │
│      │                  ├────────────────────────────────────┤
│      │ 章节/实验树       │ 教程阅读区                         │
│      │                  │                                    │
│      │                  ├────────────────────────────────────┤
│      │                  │ 底部面板                             │
│      │                  │ [终端: mysql] [输出] [错误]          │
└──────┴──────────────────┴────────────────────────────────────┘
```

插件面板的显示必须遵守：

- 插件已安装且通过当前实验包依赖解析；
- 插件获得对应的 UI 注册权限；
- 当前包的执行/网络/文件权限仍按独立权限系统判断；
- 插件缺失时显示可解释的提示，教程仍可进入只读阅读模式；
- 插件崩溃不应导致主窗口一起崩溃。

### 4.1 主窗口与辅助侧栏的选择

右侧辅助侧栏不是所有内容的固定归宿，而是一个由用户选择的辅助工作区：

- 视图可以声明推荐位置，但普通视图的最终位置由用户决定：中央主窗口、辅助侧栏或底部面板。
- 实验、沉浸式教程和需要较大操作空间的内容默认进入中央主窗口。
- AI 对话、实时诊断、环境状态等明确的辅助功能默认进入辅助侧栏。
- 辅助侧栏支持标签页、显示/隐藏和宽度调整；MVP 只保留一个辅助侧栏标签组。
- 用户移动视图后的偏好按视图 ID 保存，插件重新加载不能擅自覆盖用户选择。

### 4.2 搜索和替换

“文本搜索和替换”是 Activity Bar 的独立入口，交互参考 VSCode 的搜索视图，但只实现 LearnLab 需要的能力：

- 搜索框支持区分大小写、全字匹配和正则表达式；
- 替换框支持保留大小写和全部替换；
- 顶部保留刷新搜索结果和清空搜索结果操作，并保留结果排序、折叠/展开等必要操作；
- MVP 默认搜索当前实验包，后续可扩展到当前章节和整个学习区；不扫描学习区外的任意文件；
- 替换前显示影响文件和匹配数量，执行后支持一次撤销；正则错误不能导致应用崩溃，应在搜索视图中显示可读错误。

### 4.3 实验视图与历史

点击“实验”时，主侧边栏显示当前 Markdown 自动解析出的实验标题。点击实验：

1. 若实验标签不存在，则在中央主窗口打开新的实验标签；
2. 若标签已存在，则聚焦该标签；
3. 实验内容底部显示当前实验历史，最新记录优先；
4. 运行输出、具体报错、通过结果和操作细节进入 `experiment_history`，不混入章节阅读百分比；
5. 实验标记解析失败时，Markdown 仍可以阅读；该实验区域显示错误占位，通知宿主并提供可复制的诊断信息。

## 5. 主题、颜色和图标

### 5.1 主题变量

主题通过 CSS 变量实现，主题插件只提供经过宿主校验的变量，不直接覆盖应用结构：

```css
:root {
  --ll-activity-bg: #202020;
  --ll-sidebar-bg: #252526;
  --ll-editor-bg: #1e1e1e;
  --ll-panel-bg: #252526;
  --ll-border: #3e3e42;
  --ll-text: #cccccc;
  --ll-muted-text: #858585;
  --ll-accent: #3794ff;
  --ll-active-bg: #37373d;
  --ll-danger: #f14c4c;
  --ll-warning: #cca700;
  --ll-success: #89d185;
}
```

必须同时预留浅色主题变量，但 MVP 可以先实现一个深色主题和一个浅色主题的静态基线。

### 5.2 状态和交互

所有交互组件至少定义：

- 默认态；
- 悬浮态；
- 激活态；
- 键盘焦点态；
- 禁用态；
- 加载态；
- 错误和警告态。

颜色不能是组件内散落的硬编码值。主题变量和组件语义状态必须分离。

## 6. 学习内容视图

### 6.1 阅读模式

Markdown 阅读器是中央工作区的第一个正式视图，支持：

- 标题、段落、列表、代码块；
- Front Matter 提供的章节元数据；
- 章节内目录跳转；
- 代码复制；
- 逐步加载和明确错误；
- 未来由插件提供公式、图表、交互容器。

教程正文采用适合阅读的排版，不强行模拟代码编辑器。代码块可以使用工作台主题变量，但需要保留长代码的横向滚动。

### 6.2 实验模式

实验卡片或实验视图可以包含：

- 实验目标；
- 前置条件；
- 开始、停止、重置；
- 提示和答案；
- 运行输出；
- 分项判定反馈。

实验执行能力由插件决定，UI 只负责统一承载状态和操作，不把 MySQL 或其他环境写死在核心阅读器中。

### 6.3 视频模式

视频是可选的内容视图，不是所有实验包的默认内容：

- 支持实验包声明的视频资源；
- 视频视图可以作为标签页或分屏视图打开；
- 进度记录与文本阅读进度分开；
- 视频时间戳笔记联动属于后续功能。

## 7. 进度、搜索和笔记

### 7.1 进度显示

- 文本章节进度由滚动位置计算；
- 滚动到底视为完成；
- 实验操作不影响文本阅读完成度；
- 看过答案后通过不需要额外标记；
- 新增章节不重置未改动章节；
- 内容发生变化的章节，按内容指纹重置为 0%；
- 实验细节、报错和通过情况进入实验历史，不塞进阅读百分比。

状态栏核心保留项为：

```text
左侧：当前文档阅读进度 100% · 已加载插件 3 个
中间：插件注册的状态项
右侧：未预览消息 2
```

不显示“章节 2/8”这类章节计数。左、中、右三个区域都允许插件注册状态项；核心只占用当前文档进度、已加载插件数量和未预览消息这三个语义位置。

### 7.2 全局搜索

文本搜索和替换是 Activity Bar 的一级入口。为避免多实验包场景下结果过于嘈杂，MVP 默认搜索当前实验包；视图保留范围选择器，后续可扩展到当前章节和整个学习区：

- 搜索实验包名称、章节标题和正文纯文本；
- 返回实验包、章节、匹配片段和跳转位置；
- 不直接扫描学习区外的文件；
- 搜索索引可以先采用遍历，规模变大后再引入索引；
- 替换操作只作用于当前允许的范围，并在执行前显示影响文件与匹配数量。

### 7.3 运行时通知（独立于日志）

通知用于软件、插件、依赖、实验包等运行时事件；日志用于诊断和历史记录，两者不互相替代。

- `info` 使用主题正常色；`warning` 使用黄色；`error` 使用红色；
- 通知以右下角气泡显示，可包含标题、正文、来源和操作按钮；
- 可自动消失的通知在顶部显示与等级一致的窄亮条作为消失进度条；进度条走满后约 1 秒通知消失；
- `info` 默认自动消失；`warning` 默认自动消失但有操作按钮时等待用户处理；`error` 默认保留，直到用户关闭或完成修复；
- 重复通知按来源、等级和消息指纹进行合并，避免插件循环刷屏；
- 通知中心/未预览消息数量由状态栏右侧入口打开，查看后清除未预览状态，但不删除日志。

`fatal` 不作为普通气泡处理。主进程确认应用无法继续正常运行后，立即停止普通窗口交互、关闭其他应用窗口，只保留专用错误展示进程/窗口和错误对话框 UI；同时写入本地脱敏报告。该 UI 不等待用户确认才执行故障隔离，用户确认只用于复制报告、查看帮助或完成最终退出；若错误展示 UI 自身无法创建，则退回系统原生错误对话框后退出。

### 7.4 笔记

笔记正文使用普通 Markdown 文件，元数据可存数据库：

```text
~/.learnlab/notes/
├── packages/
│   └── sql-intro/
├── free/
└── tags/
```

核心不内置云同步。用户可以复制 Markdown、导出设置 JSON，或通过插件接入自己的同步方案。

笔记可以作为独立标签页打开，也可以与教程做分屏布局。分屏和视频时间戳联动属于后续阶段。

## 8. 面板排列和响应式规则

### 8.1 默认单列

中央工作区默认一次显示一个主视图：

```text
[教程标签]
────────────────────────
        教程内容
────────────────────────
```

### 8.2 分屏

当用户打开笔记、实验或插件视图时，可以使用双列或上下分屏：

```text
┌──────────────────────┬──────────────────────┐
│ 教程                  │ 实验 / 笔记 / AI      │
└──────────────────────┴──────────────────────┘
```

### 8.3 小窗口规则

窗口宽度不足时按以下顺序收缩：

1. 隐藏非必要的辅助文字，只保留图标和 tooltip；
2. 收窄主侧边栏；
3. 把底部面板改为覆盖式或折叠式；
4. 保证中央教程仍能阅读；
5. 不让插件视图突破宿主边界。

---

### 8.4 VSCode 源码参考边界

实现时可以参考 VSCode 开源仓库中按 Workbench Part 拆分的组织方式，尤其是 Activity Bar、Primary/Auxiliary Sidebar、Titlebar、Statusbar 和 Notifications 的边界。LearnLab 只借鉴职责分层、状态模型和生命周期管理，不复制 VSCode 品牌、图标、文案或不需要的功能；具体实现仍以 LearnLab 的 Preact/Electron 约束和插件权限模型为准。


## 9. 与 VSCode 的关系

这是**直接对标**，不是只在插件增强模式下才相似：

| VSCode Workbench | LearnLab | 说明 |
|:---|:---|:---|
| Native/Application Menubar | 跨平台原生 Menubar | macOS 使用系统菜单；Windows/Linux 在窗口内显示 |
| Titlebar / Command Center | 应用内标题区和命令入口 | 当前上下文、快速打开和命令，不复制完整 Menubar |
| Activity Bar | 章节、搜索替换、实验、插件、依赖、学习区、文件资源管理器 | 一级功能切换，使用自有图标 |
| Primary Sidebar | 实验包/章节/实验导航或当前功能面板 | 显示学习结构，而不是默认显示文件树 |
| Editor Tabs | 教程/实验/笔记/日志标签 | 只有一个主 Editor Group |
| Editor Area | 学习与实验主工作区 | 正文适合阅读，实验由插件提供 |
| Auxiliary Sidebar | AI、诊断和用户选择的辅助视图 | 支持标签；普通视图可由用户选择位置 |
| Bottom Panel | 终端、输出、诊断和实验历史 | 仅在需要时展开 |
| Status Bar | 当前文档进度、已加载插件、未预览消息和插件项 | 左/中/右槽位均可由插件注册 |
| Notification Host | 右下角运行时通知气泡 | 独立于日志；fatal 由主进程特殊处理 |
| Command Palette | LearnLab 命令入口 | 核心和插件统一注册命令 |
| Theme variables | LearnLab 主题系统 | 参考信息层级，不复制品牌资产 |

最终目标是：用户看到 LearnLab 时，能获得类似 VSCode 的稳定、优雅、可扩展的工作台体验；但用户学习的对象是实验包，而不是源代码项目。
