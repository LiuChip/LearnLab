# LearnLab｜让教程走向可动手的实验

> **项目介绍稿 · 2026-10-01**  
> LearnLab 是正在开发的本地交互式实验浏览器。本稿区分已经可以在源码中体验的阅读基线与计划中的完整实验能力；目前没有公开安装包，也不把 UI 原型当成产品演示。

## 一句话认识 LearnLab

LearnLab 希望把一份教程变成一个可分享的**实验包**：内容作者组织章节、练习、资源和环境要求；学习者在桌面应用中阅读、动手、获得反馈，并保留自己的学习记录。

它的目标不是替代老师，也不是为每一门学科内置一套庞大环境。LearnLab 负责打开和组织实验包，具体实验环境和判定能力由相应插件提供。第一条计划验证的真实链路是 MySQL。

## 为什么做这个项目

静态教程适合传播知识，却常在“现在轮到我操作”这一刻留下空白：读者需要另找环境、猜测先后步骤、判断自己做得对不对。课程作者也很难把文字、练习和运行条件作为一个整体交给别人。

LearnLab 以实验包作为共同载体，逐步连接三个环节：

| 环节 | 对学习者的意义                                 | 对作者的意义                                     |
| ---- | ---------------------------------------------- | ------------------------------------------------ |
| 阅读 | 按章节阅读，保留进度；实验与正文在同一上下文中 | 用 Markdown 整理知识，不把内容绑死在专有编辑器里 |
| 动手 | 在对应实验标签中使用受控环境，查看提示与结果   | 为每个练习声明目标、资源和环境要求               |
| 反馈 | 区分自动判定与自己判断，回看每次尝试           | 通过适配器和判定器提供领域内有意义的反馈         |

第一环节已有开发基线；后两环节的真实执行和判定仍在[后续计划](ROADMAP.md)中。

## 一个未来的学习场景

一位刚开始接触 SQL 的学习者，拿到一份 MySQL 入门实验包。他先读“如何筛选数据”，再打开对应练习；环境预检告诉他需要什么，实验标签承载真正的执行；判定器指出哪些检查项通过，失败记录保留输入、输出和步骤。隔天重新打开，他可以继续阅读并查看此前的尝试。

这是 LearnLab 要交付的**目标体验**。截至本文日期，项目已经能读取目录型课程、展示章节和进度，但尚不能从界面完成上述导入、实验运行与自动判定流程。我们选择把这个差距写清楚，让用户和合作者知道当前版本适合体验哪一段。

## 产品结构

### 实验包：内容可以独立流转

实验包将章节 Markdown、manifest 元数据以及可选的实验资源放在一个目录内。作者可以声明实验数量、所需插件、运行依赖和外部前置软件。目录型实验包已经可由核心加载；归档格式 `.labpkg`、安全导入和作者打包 CLI 仍在规划与实现中。

内容与环境分离的意义是：同一份教程不必把 MySQL、编译器或其他专业工具直接塞进阅读器。学习者即使暂时没有相应环境，也应能继续阅读可读的章节，并得到明确的缺失说明。

### 学习区：把相关课程放在一起

学习区是用户本地的课程容器。它可以登记多个实验包，记录包位置、共享依赖和阅读状态。当前桌面应用会打开默认学习区，并显示其中已登记的课程；创建、切换以及从界面导入课程是近期需要补齐的体验。

项目以本地文件为数据基础，不要求用户先创建账号。配置可以导入和导出；学习区及课程数据需要单独备份，配置文件本身不是完整备份。

### 插件：让不同学科保持自己的工具

插件将来提供环境、命令、判定器和受控的界面扩展。LearnLab 已实现插件 manifest 解析、全局/当前包依赖关系计算，以及读写执行权限的纯逻辑求交；**实际插件代码加载、授权和执行宿主尚未接入**。目前目录中的官方插件是后续实现位置，不是可用的 MySQL 或终端产品。

我们的设计原则是让插件只能申请当前任务需要的能力，并在运行代码前告知用户风险。应用计划使用独立宿主和执行监督降低故障影响，但不会把这种机制宣传为操作系统级沙箱。

## 现在可以看到的进展

| 已有基础       | 具体边界                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 桌面工作台     | Electron + Preact 的章节、标签、侧栏、搜索、状态与通知区域；正式视觉仍在验收和修订                     |
| 阅读与进度     | 目录型实验包解析、Markdown/GFM 渲染、章节阅读进度、内容变化后的进度处理                                |
| 学习数据       | 学习区与包内状态分层，配置 JSON、历史文件模块与迁移机制；部分会话恢复尚未接线                          |
| 插件和依赖基础 | 注册表、依赖解析、缺失状态、权限求交与 bundled dependency 安全导入；没有真实插件执行                   |
| 质量门禁       | 2026-10-01 工作树的 123 项测试通过；TypeScript 检查、lint 和开发构建通过；这不是安装包或跨平台实验验收 |

当前正式 UI 的搜索仍使用核心学习区遍历能力。现行交互设计将先开放**当前文件查找**，并在界面中把当前实验包、当前学习区两种范围明确标为后续能力；这项 UI 对齐列为近期任务。

## 接下来的交付顺序

| 里程碑         | 对用户可感知的变化                                                 |
| -------------- | ------------------------------------------------------------------ |
| M1：阅读入口   | 在界面中登记本地实验包、切换学习区，完成当前文件查找和基础会话恢复 |
| M2：实验内容   | 从章节打开实验标签，查看目标、提示及已有尝试历史                   |
| M3：受控执行   | 插件在独立宿主内运行，执行过程可取消、超时并清理专用进程           |
| M4：真实课程   | 完成可执行的 MySQL 示例，能预检、运行、判定、重置并回看历史        |
| M5：分享与发布 | 完成包归档/作者 CLI、下载源、目标平台安装包和正式视觉验收          |

完整任务、涉及既有代码的修改范围与验收标准见[路线图](ROADMAP.md)。里程碑表达依赖关系，不是发布日期承诺。

## LearnLab 适合谁参与

**学习者**可以关注阅读体验、初次使用路径、错误信息是否容易理解；在实验执行完成前，适合试用的是章节浏览，而不是实际 MySQL 课程。

**内容作者和教师**可以帮助验证实验包元数据、章节组织、练习目标与反馈粒度。当前可用目录型示例做格式讨论，面向作者的打包 CLI 和可视化工具尚未发布。

**开发者**可以参与本地包导入、搜索交互、插件宿主、进程监督和跨平台数据兼容。源码是 pnpm monorepo；当前 API 表中的内部接口并非稳定第三方 SDK。
