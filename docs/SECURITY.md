# 安全机制

> 相关文档：[插件加载与 API 设计](superpowers/specs/2026-09-01-plugin-loading-and-scoped-permissions-design.md) · [架构设计](ARCHITECTURE.md) · [路线图](ROADMAP.md) · [数据模型](DATA_MODEL.md)
>
> 设计目标：对普通用户诚实说明风险，并用作用域限制、独立插件宿主和执行监督降低误操作风险；不把本地进程限制冒充成 OS 沙箱。

LearnLab 会打开本地内容、调用插件和运行实验环境。任何“执行代码”能力都必须由用户主动授权。普通用户最重要的安全保证是：未知实验包默认可阅读、执行能力单独确认、插件不能默认访问学习区中的其他内容。

---

## 🔒 实验包权限声明

```yaml
security:
  sandbox: untrusted       # untrusted / trusted / self，仅表示信任等级
  capabilities:
    - package.read
    - package.write-runtime
    - execution.request
  network: false
```

权限声明用于展示和授权；实际能力来自实验包所需插件的 capability 声明，不等于实验包可以自行绕过宿主限制。实验包中的初始化脚本、外部命令、依赖安装和环境适配器调用，都必须经过执行监督器。权限不按少数插件类型硬编码，而由插件声明通用能力和执行计划；由于项目不做 OS 级沙箱，允许执行强大外部程序时仍可能间接触达作用域外资源，开发者模式必须显式警告。

### 用户导入流程

```text
导入 .labpkg
  ↓
解析 manifest、校验包结构和完整性
  ↓
展示作者、来源、目标、环境、权限和风险
  ↓
默认进入“仅阅读”或请求用户授权执行
  ↓
用户选择：拒绝 / 仅本次 / 对该包始终允许
  ↓
记录最小信任决策，并允许在设置中撤销
```

权限弹窗应明确写出“不能保证 OS 级强隔离”。如果包声明执行 Shell、安装依赖、访问网络或访问用户目录，应使用更明显的风险级别。

---

## ⚖️ 安全级别

| 信任等级 | 含义 | 默认能力 |
|---|---|---|
| `untrusted` | 未知来源 | 只读优先；执行需单独确认；进程由宿主监督；不承诺 OS 沙箱 |
| `trusted` | 用户明确认可的作者/包 | 可按声明执行；仍受宿主作用域、命令和进程监督约束 |
| `self` | 用户本人制作/开发 | 可进入开发者模式；允许更宽权限，但每次进入都显示风险 |

“自定义源由用户自己管理”不代表 LearnLab 认为内容安全。源只负责提供内容，用户仍需自行判断作者和实验包。

## 🛡️ 插件权限与作用域

插件权限与实验包权限分开管理。插件默认运行在独立宿主进程中，主进程只向它暴露白名单 API；“已安装”或“全局激活”都不等于获得所有文件和进程权限。

### 上下文与默认作用域

核心向插件提供两个主要上下文：

- `AppContext`：软件全局作用域的只读抽象，可读取 LearnLab/API 版本、已安装插件摘要、经授权的设置，并注册面板、按钮、命令等 UI 扩展；
- `PackageContext`：当前实验包作用域，可按授权访问当前包静态内容、`.learnlab/` 动态区、当前实验和依赖环境。

学习区组织关系由核心内部的 `WorkspaceContext` 管理。插件默认不能直接访问学习区数据库、其他实验包、共享依赖目录或任意家目录；有需要时只能申请一个明确的高层 API 和额外授权。

### 权限分层

插件 manifest 的权限顶层固定分为 `read`、`write`、`execute`，但具体资源和动作采用开放字符串声明：

| 权限 | 第一版允许的细分项 |
|:---|:---|
| `read` | LearnLab/API 版本、已安装插件列表、被暴露的设置、当前实验包/章节/实验、当前包依赖和会话摘要；学习区包摘要需额外授权 |
| `write` | 剪贴板、当前实验包 `.learnlab/`、插件设置新属性、被授权的设置、当前包环境变量、面板/按键/右键菜单/命令注册 |
| `execute` | 网络请求、当前包附带可执行文件和环境、用户在当前包内主动执行的代码、外部文件选择请求、核心执行计划 |

建议 manifest：

```yaml
plugin_id: "org.learnlab.mysql"
version: "1.2.0"
author: "LearnLab Contributors"
signature: "..."       # 身份/发布信息；没有验证链时不代表安全认证
api_version: 1
activation:
  mode: package         # global | package
permissions:
  read:
    - package.manifest
    - package.files:chapters/**
  write:
    - package.runtime
  execute:
    - package.process
    - network.request
breaking_change: false
```

插件身份只要求 `plugin_id`、版本、作者和签名信息；不额外引入复杂的市场评级或企业级审批体系。兼容更新应尽量让使用旧插件的实验包无感升级；破坏性更新必须显式标注。

### 权限求交与开发者模式

实际授予权限采用求交规则：

```text
有效权限 = 插件声明
         ∩ 当前包请求的作用域
         ∩ 用户授权
         ∩ LearnLab 核心策略
         ∩ 当前平台支持能力
```

全局插件（例如 Vim 模拟、主题或全局快捷键）对所有实验包可用，但仍需按当前包创建 `PackageContext`，不会因为全局激活就获得所有实验包的读写权限。插件宿主进程可以延迟启动，避免把“全局可用”误解为“每次启动都执行一份进程”。

开发者模式可以申请更大的文件、外部进程或网络权限。启用时必须显示：

> 当前插件可能执行任意本机操作，包括读取、修改或删除文件，以及启动外部进程。仅建议对自己编写的插件使用。

“作用域限制”是 API、工作目录、资源句柄和执行计划层面的约束，不是 OS 级沙箱；如果插件启动了足够强的原生程序，LearnLab 不能承诺该程序绝对无法接触作用域外资源。

### 当前包的插件加载

实验包的插件集合由当前包直接依赖和递归依赖链决定，全局插件始终加入：

```text
ActivePlugins(package)
  = GlobalPlugins
  ∪ Closure(package.required_plugins)
  ∪ Closure(GlobalPlugins.requires_plugins)
```

缺少、停用、不兼容或依赖冲突的插件不能静默跳过。打开实验包时显示受影响的插件和功能；用户可以继续阅读，但依赖该插件的实验或命令只能在授权/修复后运行。全局插件的依赖缺失时，该全局插件在所有受影响的包中显示为阻塞。

## 🧰 运行时作用域和执行监督

适配器可以生成执行计划，但最终启动、超时、取消和回收由内核 `ExecutionSupervisor` 负责。

执行监督至少处理：

- 插件声明的能力是否已获授权；
- 执行计划中的程序、参数、工作目录和资源句柄是否符合当前授权；
- 工作目录是否位于当前实验包作用域；
- 环境变量是否包含密码、令牌等敏感信息；
- 超时时间和最大输出量；
- 进程树终止和孤儿进程清理；
- 插件/适配器崩溃后的状态恢复；
- 运行日志的截断和脱敏。

```typescript
interface ResourceLimits {
  timeout_ms: number
  max_memory_mb?: number
  max_output_bytes?: number
  max_processes?: number
}
```

跨平台资源限制的实现细节由内核执行监督器和适配器共同完成；适配器不能以“自己负责”为理由绕过内核。

## 🩺 环境预检

包加载后按包粒度执行预检，避免每个实验重复扫描。预检包括：

- 所需插件及版本是否满足；
- MySQL/Python/Java 等环境是否存在；
- 平台是否支持；
- 声明式依赖是否完整；
- 当前路径是否可读写；
- 运行目录是否可以创建。

预检结果只作为缓存提示。用户在预检后关闭服务或删除依赖时，开始实验仍可能失败，此时进入错误诊断流程。

## 🔥 崩溃与错误诊断

诊断报告只保存在本地，不自动上传。报告分为“用户可读摘要”和“完整日志”，复制前默认脱敏。

### 报告中允许保留

- LearnLab 版本、系统和架构；
- 包 ID、包版本、插件 ID 和版本；
- 实验 ID、阶段和退出码；
- 脱敏后的命令摘要；
- 截断后的日志尾部。

### 默认脱敏

- 用户名和绝对路径替换为 `<USER>`；
- 环境变量值、密码、Token、连接串凭据全部删除；
- 用户代码和实验输出默认只保留在本地，复制前由用户确认；
- 日志大小有上限，避免复制超大内容。

```json
{
  "learnlab_version": "0.1.0",
  "os": "macOS",
  "arch": "arm64",
  "package": "org.learnlab.mysql-intro@1.2.0",
  "plugin": "org.learnlab.mysql@1.2.0",
  "lab_id": "ch2-3-1",
  "phase": "setup",
  "command_summary": "mysql dependency setup",
  "exit_code": 1,
  "error": "connection timed out",
  "log_tail": "...",
  "redactions": ["absolute_path", "secret"]
}
```

界面提供：查看完整日志、复制脱敏报告、重试、打开帮助。实验没有崩溃但用户卡住时，也可以复制“求助上下文”，但仍必须经过同样的脱敏确认。

## 🧱 Markdown 渲染边界

为保证 Markdown 编辑器的基本功能，LearnLab 允许实验包和笔记使用原始 HTML、包内相对路径、本地 URL、图片和嵌入式资源。这里的“允许”是渲染能力，不等于内容获得 Electron 主进程、Node.js 或任意 IPC 权限。渲染进程必须保持隔离，不能开启 `nodeIntegration`，只能通过最小 preload API 与主进程通信。视频不要求 Markdown 直接承载：视频作为独立选项卡打开，Markdown 通过 LearnLab 链接或容器引导用户打开对应视频。

如果未来允许远程资源或脚本型渲染扩展，应单独展示网络/脚本风险；MVP 不把 Markdown 内容直接当作插件代码执行。

## 📦 包完整性和导入保护

LearnLab 不试图判断 GitHub 或自定义源是否绝对可信，也不建立复杂的市场审核体系；只保证下载的实验包在传输和导入过程中完整正确：

- 校验文件大小和 SHA-256；
- 使用临时目录解压，成功后再提交到学习区；
- 拒绝路径穿越、绝对路径和非法链接；
- 限制压缩包大小和解压后总大小；
- manifest 校验失败时只显示错误，不执行其中脚本。

包的作者、目标、前置知识、环境、日志和许可证由作者标注，用户自行判断质量。后续可以用 GitHub star 作为展示信息，但不把 star 当作安全证明。
