# 测试策略

> 相关文档：[路线图](ROADMAP.md) · [公开决策索引](DECISIONS.md) · [文档状态](STATUS.md)
>
> 目标：用小项目能够承担的测试成本，保护“导入 → 阅读 → 运行 → 判定 → 保存 → 恢复”这条主链路。
> 下列是目标验收范围，并非当前全部通过；已完成的 123 项测试不能替代尚未开发的实验端到端验证。

## MVP 必测范围

### 1. 包解析和导入

- 合法/非法 `manifest.yaml`；
- 重复 `package_id` 或 `lab_id`；
- 缺失章节、实验文件和资源；
- 路径穿越、绝对路径和异常压缩包；
- SHA-256 或文件大小不一致；
- 导入失败时不留下半成品目录。

### 2. 学习区和数据库

- 新建、打开、切换学习区；
- 登记实验包和软连接；
- 包移动后按设计提示进度可能丢失；
- `workspace.db` 和 `package.db` 首次创建；
- 核心硬编码 migration 按顺序执行、可重复启动且失败不破坏原库；
- 数据库损坏时进入只读或可恢复错误页。

### 3. 阅读和进度

- 滚动到底标记章节已读；
- 关闭并重新打开后恢复已记录的阅读进度；当前包/章节/滚动位置是下一步会话目标，标签页和语言是否恢复需先冻结范围；
- 未修改章节保留已读状态；
- 内容指纹变化的章节重置为 0%；
- 实验通过/失败不改变阅读百分比；
- UI 根据实际发现的 Markdown 章节渲染，实验总数使用 manifest 的 `experiment_count`，扫描结果只用于校验；
- 新增未修改章节不重置旧章节进度，修改已有章节按内容指纹重置为 0%；
- 当前文件查找只匹配当前教程章节，并能定位、高亮、上/下跳转；章节切换、空输入、非法正则与过期请求不保留旧结果。当前实验包/学习区范围在 MVP UI 中不可选；核心遍历搜索和未来索引分别测试，不把索引视为当前依赖。

### 4. MySQL 黄金路径

```text
导入包
→ 环境预检
→ 在章节卡片点击“打开实验”（仅打开或聚焦标签）
→ 在实验标签内执行
→ 执行错误命令
→ 展示结构化失败
→ 查看提示
→ 重置
→ 执行正确命令
→ 判定通过
→ 关闭实验标签时确认专用进程已退出，必要时强制回收
→ 关闭应用
→ 重新打开并查看状态和历史
```

### 5. 执行监督和错误报告

- 超时可以终止当前进程；
- 执行监督器取消、超时和关闭标签时不会留下本实验专用进程，也不会误杀共享依赖或其他实验；实验页无需独立停止按钮；
- 输出过大时截断而不是占满内存；
- 适配器崩溃不拖垮主界面；
- 复制报告会脱敏绝对路径、Token、密码和敏感环境变量。

## 插件加载与权限测试

- 全局插件在每个实验包的活动集合中出现；
- 当前包只激活 manifest 直接依赖及插件递归依赖，不加载无关包级插件；
- 全局插件的传递依赖同样被解析；
- 缺失、停用、API 不兼容、版本冲突和循环依赖返回不同状态，并触发只读/阻塞提示；
- 同一 `plugin_id` 的版本范围可合并时选择一个版本，不能合并时当前包只读；
- `AppContext` 可读取的全局信息有限，`PackageContext` 切换后不会复用上一个包的路径和文件句柄；
- 全局激活不会自动获得其他实验包、`workspace.db` 或整个学习区的文件权限；
- 读、写、执行权限按 manifest、当前包范围、用户授权、核心策略和平台能力求交；
- 依赖相同 ID、版本、平台、架构和 SHA-256 的实验包复用学习区 `dependencies/`，不同哈希可以并存；
- 实验包自带的 `bundled-dependencies/` 导入后与仓库依赖进入同一存储路径；
- 当前平台没有依赖构建变体时返回明确的不可用状态；
- 依赖下载或导入失败不留下半成品，也不覆盖已有可用实例；
- `external_prerequisites` 只触发插件检测和用户可见交互，不触发核心静默安装。

## 插件的最小契约测试

插件生态阶段只要求少量高价值测试，不建立企业级认证体系：

- manifest 可以解析；
- ID、版本、作者和签名字段存在；
- 依赖的 API 版本和能力可以协商；
- 插件只能通过宿主 API 访问当前实验包；
- 插件只能获得与当前活动集合匹配的上下文，缺失插件时核心必须提示而不是静默忽略；
- 开放能力采用通用 capability 声明，不依赖少数固定插件类型；
- cleanup 后不留下临时运行文件；
- 插件崩溃后可以停用并重新启动。

## 平台验证

MVP 先记录实际支持的平台和已知限制，不承诺一次覆盖所有系统。至少在开发环境验证：

- macOS 当前开发机；
- 一个 Linux 环境；
- Windows 如有条件再验证。

重点关注路径、Shell、MySQL 服务、子进程回收、中文路径和打包后的原生依赖。

## 不在 MVP 强制要求

- 平台模拟器；
- 第三方插件全量安全审计；
- 复杂 fuzzing 平台；
- 云同步冲突测试；
- 教学质量自动评分；
- 无障碍完整认证；
- 自动更新/OTA 的升级通道和回滚体系。
