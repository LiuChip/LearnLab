# LearnLab 插件加载与分层权限设计

> 日期：2026-09-01

## 1. 目标与范围

本设计解决四个问题：

1. 插件如何区分软件本体、学习区和当前实验包的作用域；
2. 插件如何以读、写、执行三类权限接入，而不把 API 做成无法维护的固定插件类型列表；
3. 当前实验包如何根据直接依赖和依赖链加载插件，同时保证全局插件对所有实验包可用；
4. 学习区如何统一保存多个实验包共享的运行依赖，并保留用户可复制的本地存储模型。

本设计不引入账号、云服务、中心化插件市场、企业级签名认证、OS 级沙箱或复杂的插件废弃周期。

## 2. 作用域模型

插件通过宿主 API 获得上下文，不直接读取 LearnLab 安装目录或扫描父级目录。上下文分为：

- `AppContext`：软件全局作用域的只读抽象。提供 LearnLab 版本、API 版本、已安装插件摘要、全局设置中被授权暴露的部分，以及命令/面板注册入口。它不是业务代码可以随意写入的可变全局变量。
- `PackageContext`：当前实验包作用域。提供包 ID、包根目录下经授权的静态文件、`.learnlab/` 动态区、当前实验和当前会话。
- `WorkspaceContext`：学习区组织关系由核心内部使用，默认不直接暴露给插件。只有确有需要且用户授权的 API 才能提供有限的学习区信息，例如包列表摘要或包间联动命令。

默认情况下插件只能使用 `AppContext` 和当前 `PackageContext`。当前实验包目录不等于整个学习区；学习区中的其他实验包、`workspace.db`、配置文件、用户家目录和外部文件均不在默认作用域内。

开发者模式可以申请更大的文件、网络或外部进程能力，但进入时必须明确提示“插件可能执行任意本机操作”。这属于风险开关，不是安全保证。

## 3. 能力与权限

插件 manifest 同时声明：

- `provides`：插件向 LearnLab 提供的领域能力，例如 `environment.mysql`、`validator.mysql-schema`、`editor.vim-mode`；实验包依赖的是这些能力或插件 ID。
- `permissions`：插件运行时需要宿主授予的动作权限。顶层分为 `read`、`write`、`execute`，每项再按资源、动作和作用域细分。

### 3.1 读权限

第一版支持以下高价值读取项：

- LearnLab 版本、API 版本和运行平台摘要；
- 已安装插件的 ID、版本、作者和状态；
- 经用户允许暴露的全局设置和当前插件设置；
- 当前打开的实验包、当前章节、当前实验和会话摘要；
- 当前实验包 manifest、章节资源和包内运行目录；
- 当前学习区的依赖摘要，以及当前包解析出的依赖链；
- 在用户显式授权后读取学习区的包摘要，不直接读取其他包文件。

### 3.2 写权限

第一版支持以下高价值写入项：

- 写入剪贴板；
- 写入当前实验包 `.learnlab/` 运行目录；
- 创建插件自己的设置项，或修改用户明确授权的设置项；
- 修改当前插件允许使用的环境变量；
- 注册和更新插件面板、按钮、右键菜单、命令和状态提示；
- 请求框架打开外部文件，并由核心以资源句柄方式交付，而不是把任意路径永久暴露给插件。

插件不能通过“写设置”间接修改核心安全策略，也不能直接修改其他插件的私有设置、学习区数据库或其他实验包文件。

### 3.3 执行权限

第一版支持以下执行类别：

- 发起网络请求；
- 执行实验包声明的依赖环境和附带可执行文件；
- 在当前实验包作用域内执行用户主动触发或明确授权的代码；
- 请求访问外部文件，由核心弹出系统文件选择器并交付临时资源句柄；
- 启动由环境适配器生成的执行计划。

所有外部进程、网络请求和代码执行都要经过 `ExecutionSupervisor` 或对应的核心服务。插件宿主隔离和 API 作用域是降低误操作风险的机制，不宣称能够抵御恶意原生程序的 OS 级攻击。

### 3.4 权限求交

实际授予权限不等于 manifest 声明的简单相加，而是以下集合的交集：

```text
有效权限 = 插件声明
         ∩ 当前包请求的作用域
         ∩ 用户授权
         ∩ LearnLab 核心策略
         ∩ 当前平台支持能力
```

插件即使被标记为全局激活，也不会因此自动获得所有实验包文件的读写权。

## 4. 插件身份、加载模式与依赖

插件身份采用接近 Maven 坐标的最小形式：`plugin_id`、版本、作者、签名。第一版不引入复杂注册中心、评分体系或企业级审核。

```yaml
plugin_id: "org.learnlab.mysql"
version: "1.2.0"
author: "LearnLab Contributors"
signature: "..."
api_version: 1
activation:
  mode: package             # global | package
provides:
  - environment.mysql
  - validator.mysql-schema
requires_plugins:
  - id: "org.learnlab.io-match"
    version: ">=1.0.0 <2.0.0"
permissions:
  read:
    - package.manifest
    - package.files:chapters/**
  write:
    - package.runtime
  execute:
    - package.process
    - network.request
breaking_change: false
```

### 4.1 两种加载模式

- `global`：插件对所有已打开实验包都处于可用状态，例如 Vim 模拟、全局主题、全局快捷键增强。它的宿主进程可以按需启动，但解析、注册和权限状态对每个包都可见。
- `package`：插件只在依赖它的当前实验包上下文中激活。激活集合由当前包的直接声明和插件的递归依赖闭包组成。

### 4.2 解析公式

```text
ActivePlugins(package)
  = GlobalPlugins
  ∪ Closure(package.required_plugins)
  ∪ Closure(GlobalPlugins.requires_plugins)
```

其中 `Closure` 会递归解析插件的 `requires_plugins`。实验包只声明直接依赖，不需要把完整传递依赖重复写入 manifest。

一个插件 ID 在 MVP 中只允许解析出一个活动版本。若多个依赖要求无法合并，当前包进入只读状态并提示冲突；MVP 不实现同一插件多版本并行宿主。

### 4.3 状态与失败处理

核心至少区分：

- `installed`：已安装但当前包不需要；
- `active-global`：全局激活；
- `active-package`：当前包激活；
- `missing`：manifest 声明但未安装；
- `disabled`：用户停用；
- `incompatible`：版本或 API 不兼容；
- `blocked`：依赖缺失、冲突或循环；
- `read-only`：包可以阅读，但所需执行能力不可用。

缺少或不可用的插件不能静默跳过。打开包时先展示缺失列表和受影响的功能；用户可以继续阅读，但开始实验、执行命令或使用对应 UI 时必须再次提示。依赖循环和版本冲突属于解析错误，应给出链路。

全局插件的缺失依赖不应只在某个包内报错，而应把该全局插件标记为 `blocked`，同时在所有受影响的包中展示统一原因。

## 5. 学习区依赖存储

实验包 manifest 只声明依赖需求；依赖的实际安装和复用由学习区管理器负责。学习区根目录新增 `dependencies/`，不同实验包如果依赖相同指纹的环境，只保留一份；不同版本或不同平台指纹可以并存。

```text
学习区/
├── .learnlab/
│   └── workspace.db
├── dependencies/
│   ├── python/<dependency-fingerprint>/
│   ├── mysql/<dependency-fingerprint>/
│   └── ...
├── package-a/
└── package-b/
```

`DependencyManager` 负责解析包声明、计算依赖指纹、选择共享目录、执行用户授权后的安装，以及报告缺失/失败状态。它不把依赖安装结果写进第三个数据库；状态摘要可记录在 `workspace.db`，具体文件始终留在 `dependencies/`。

## 6. 生命周期

```text
导入包
  → 校验 manifest
  → 注册到学习区 workspace.db
  → 解析全局插件
  → 解析当前包直接插件和传递依赖
  → 检查插件版本、API、权限和学习区依赖
  → 展示缺失/风险
  → 用户授权后启动插件宿主
  → 注册 UI/命令/能力
  → 打开包或进入只读模式
```

切换实验包时重新计算当前包的 `PackageContext` 和包级插件集合；全局插件保留其全局状态，但不能把上一个实验包的文件句柄带入新包。

## 7. 不在本设计内

- 云同步、账号、冲突合并和远程备份；
- 实验历史的数据库化；具体运行细节继续保存在 `experiment_history/`；
- OS 级沙箱、容器或完整第三方插件安全审计；
- 插件废弃周期和复杂迁移协议；兼容更新尽量无感，破坏性更新必须显式标注；
- 学习区之间的全局搜索和跨设备进度绑定。
